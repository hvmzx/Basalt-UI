basalt serve MODEL.basalt [--python PY] [server args...]
    runs the Python server (serve/) over this binary: the server reads its options and the engine flags
    from the config file and the command line (the model is the config's or MODEL.basalt, which stands
    for --model); --python defaults to .venv/bin/python in the source tree, else python3; the other
    arguments go to the server.  It runs in the source tree; --model and --config paths are made absolute.
basalt generate --model FILE.basalt --tokens "1,2,3" [options]

  --model FILE         the .basalt model file (required): the dense weights, experts, source tensors
                       (embedding, PLE table, native projections, head), draft layer and 8-bit
                       hyper-connection copies all come from it; the expert profile from
                       --expert-profile, else data/profiles
  --expert-profile P   the expert profile to place at start (the format of data/profiles)
                       instead of the engine's own for the model
  --tokens LIST        the prompt as comma-separated token IDS (required)
  --tokens-file PATH   pretokenized prompt, commas or whitespace (alternative to --tokens)
  --ple-io direct|ram  n-gram table reads. direct (default): 4 KiB SSD
                       reads, the table stays out of the engine's memory; ram: mmap with the whole table locked in RAM 
at start
  --ple-row-cache N    bounded cache of fetched rows, 90 B each (default 1048576; 0 = off)
  --ple-inflight N     outstanding SSD reads (default 256)
  --ple-delay-us U     fault injection: each row read completes no earlier than U us
  --kv fp16|int8       KV storage: int8 codes + fp16 scale per 64 values, half the
                       VRAM; default fp16
  --kv q4_0            4-bit K/V after a Hadamard rotation: half of int8's memory,
                       slightly lower precision
  --kv k8v4            hybrid: INT8 K (exact attention scores) + rotated Q4_0 V, 816 B/cell
                       (vs int8's 1,056); not with --kv-resident
  --kv fp8             compressed-attention caches (their default): FP8 window rows and FP4
                       compressed rows and index keys, rounded as the model's reference; fp16 keeps
                       them unrounded. Each model takes its own --kv values (docs/models)
  --kv-resident N      KV streaming: keep N cells of each QSA layer in VRAM (min 20480) and the
                       whole K/V in pinned RAM; the freed VRAM goes to expert slots. 0 (default):
                       all of it in VRAM. A context of N cells or fewer is not streamed
  --serve              stay resident and take requests on stdin (the server's mode)
  --exp NAME=VALUE[,...]  diagnostics; concur9_logit_hash=1 prints a hash of each accepted row's
                       logits on stderr
  --gpu A,B,..|auto    the GPUs to use, as nvidia-smi numbers them (within CUDA_VISIBLE_DEVICES when
                       set): exactly these, the first the main card; the engine gives the rest their
                       roles.  auto = every Blackwell card, the fastest as main.  Default: GPU 0 alone
  --gpu-plan           print the --gpu choice as one JSON line and exit (no model needed)
  --mtp-window N       the drafter attends to the last N cells (default 32768; 0 = every cell)
  --stop-eos           stop when the model emits an end-of-turn token
  --eos-ids LIST       the end-of-turn token ids for --stop-eos (default the pack's); implies it
  --prompt-cache-root N  --serve: checkpoint a prompt's first turn boundary when it is at least N tokens
                       long (default 2048, 0 = never)
  --max-new N          tokens to generate (default 16)
  --max-context N      KV/state capacity (default 8192)
  --rope-scaling T     extend the context past the trained one: none, linear
                       (position interpolation) or yarn - llama.cpp's types and names.
                       Default: the model file's rope keys, else none. Fixed at startup:
                       K in the cache is post-RoPE, so one run one scaling
  --rope-scale F       the extension factor for linear/yarn (default: the model file's
                       factor, else 1 = off)
  --rope-freq-base N   the raw ggml knobs: the frequency base (0 = the model's 1e7) and
  --rope-freq-scale F  the angle shrink (0 = 1/--rope-scale)
  --yarn-orig-ctx N    the trained context the correction targets (0 = 262144)
  --yarn-ext-factor F --yarn-attn-factor F --yarn-beta-fast F --yarn-beta-slow F
                       YaRN's knobs; defaults: -1 (auto: 1 for yarn), 1, 32, 1
  --greedy             argmax (the default)
  --seed S             enable sampling with this Philox seed
  --top-k N --top-p F --temperature F
  --dump-residual PATH write the final R (hc x n_embd, f32) for head bisection
  --dump-routing PATH  write the routed expert ids and weights per layer per position
  --no-capture         run the layers directly instead of replaying graphs
  --vision             --serve takes images, encoded in this process (it reads the model file's
                       vision/mmproj in place): ENC requests borrow expert-cache slots for the
                       encoder and give them back refilled
  --vision-external    --serve takes images whose embeddings come from basalt-vision --model FILE
                       (GENI requests)
  --no-prompt-skip     a model that stops far prompt rows short runs them through every layer: slower
                       reads, the same math from the last prompt token on, another batch shape's rounding
  --prompt-cache N     --serve: keep N conversation checkpoints between requests (default 6, ~118 MB
                       of RAM each; 0 = read every prompt from the start)
  --conversation-cache-mib N  --serve: RAM budget for parked conversations (default 0 = off)
  --conversation-cache-slots N  --serve: at most N parked conversations (default 4)
  --conversation-cache-min-free-mib N  --serve: physical RAM floor when parking (default 2560)
  --ram-reserve-mib N  RAM left free for the rest of the system (default 2048); the expert tiers leave
                       it and the --serve RAM guard holds it (0 = keep nothing, guard off)
  --conversation-cache-min-tokens N  --serve: park only conversations of at least N tokens (default 0 = park every one)
  --conversation-cache-disk-mib N  --serve: park conversations on disk, at most N MiB, and read them back
                       when a prompt starts with one, also after a restart (default 0 = off)
  --conversation-cache-dir DIR  --serve: the disk tier's folder (required with a budget unless the
                       server starts the engine, which uses the model cache folder)
  --vram-elastic       --serve (opt-in): the expert cache in segments (--vram-segment-mib,
                       default 512), so the command `VRAM <reserve_mib>` (the server's POST /v1/vram) can
                       give VRAM back to other programs between requests and take it back later
  --batch N / --slots N  --serve (opt-in): up to N requests decode together in batch slots (2..8),
                       each slot with its own session (VRAM like the main one; with --kv-resident
                       and --kv int8 its K/V streams from RAM like the main one's)
  --prompt-cache-every N  --serve: also checkpoint every N fresh prompt tokens (default 16384, 0 = off)
  --turn-token ID      --serve: the token that opens a chat turn (default the pack's)
  --tail-role-token ID --serve: a turn of this role right before the last turn is left out of
                       the conversation checkpoint (a trailing effort turn; default -1 = off)
  --short-read N       --serve: read at most N fresh text tokens through the decode windows instead
                       of the batched prompt path (default 64, 0 = off)
  --suffix-draft N     prompt lookup: draft from an earlier repeat of the last N+ tokens of context
                       when it pays (default 3; 0 = MTP only)
  --spec N             speculative decoding: verify windows of at most N tokens (the last accepted
                       token plus up to N-1 MTP drafts, sized per window by the drafts' joint chance
                       of acceptance against a threshold adapted per request); 0 or 1 = no
                       speculation (default: the pack's drafter decides, 8 with an MTP drafter
                       and 3 with a DSpark one; 0 without a drafter)
  --draft-experts N    a DSpark drafter keeps each stage's N most routed experts by the shipped ranking
                       (32, 64, 96 or 128; default 32; 0 = all)
  --relaxed-drafting [P]  sampled requests keep a draft the target gives probability >= P even when
                       the target's own draw differs: faster, but NOT the exact sampling distribution
                       (docs/precision/qwen38-flash-next.md#relaxed-drafting).
                       P in (0, 1]; lower is faster and further from exact; the flag alone = 0.5.  Tool calls,
                       control tokens, logit_bias and greedy requests stay exact.  Default off (exact)
  --route-tail-skip [R]  a decode window drops a routed expert no GPU holds when every entry naming it
                       ranks R or lower by router weight (0-based of 10): neither copied nor computed,
                       the others keep their weights.  Faster, but LESS ACCURATE than the model
                       (docs/precision/qwen38-flash-next.md#lossy-routing-flags).
                       R in 1..9, lower drops more; the flag alone = 9.  Needs the device-planned MoE tail.
                       Default off (exact)
  --route-prior [LAMBDA]  a decode window picks its ten experts as if each one a GPU holds had LAMBDA
                       added to its router logit; the weights stay the router's.  Faster, but LESS
                       ACCURATE than the model (docs/precision/qwen38-flash-next.md#lossy-routing-flags).
                       LAMBDA in (0, 16], higher routes harder toward held experts; the flag alone = 0.5.
                       Needs the device-planned MoE tail.  Default off (exact)
  --grammar on|off     --serve: enforce a request's "grammar" (tool-call, JSON-schema or JSON-object
                       grammar) on the sampled tokens; the vocabulary comes from the pack.  Default off
  --mtp-max-t M        cap the MTP's windows at M tokens (0 = --spec; longer ones come from suffixes)
  --control-vector-scaled FILE:SCALE[,...]  a control vector GGUF on the residual stream (llama.cpp's
                       format; --control-vector FILE = scale 1).  --serve: requests switch it (cvec=0|1)
  --control-vector-layer-range A B  the layers it follows (inclusive; default 1 .. the last)
  --cvec-mode add|project  h += s v (default) or h -= s (h.v) v with v unit
  --cvec-dir per-layer|single:L  each layer's own direction (default) or layer L's everywhere (project)
  --prefill CHUNK      batched prompt processing in chunks of CHUNK tokens (default auto); auto = the fewest

                       what the expert cache can lend (with --resident-experts the lent slots the
                       RAM copy backs, else 8192); auto:N (8192, 16384, 32768) sets the ceiling
  --no-pool            skip the CPU expert pool (the GPU-only floor)
  --dump-mixed PATH    write the post-attention residual (n_embd, f32)
  --stage-timing       per-stage KERNEL-COUNT shares.  NOT a time profile: an uncaptured
                       event interval includes host gaps, so run with --gpu-only-full first
  --graph-only         MEASURE: replay the 48 `pre` graphs only.  OMITS the 48 `post` graphs
                       and the LM head, so it is NOT the GPU floor
  --gpu-only-full      MEASURE: replay pre+post for all 48 layers plus the LM head, no pool.
                       THE TRUE PER-TOKEN GPU FLOOR.  Quote this one, not --graph-only.
  --stats              print the per-stage breakdown
  --profile            GPU stage times of the decode windows (serve path)
  --wait-stats         the host's wait times in the decode loop (serve path)
  --decode-timing      one line per request: where its decode time went (serve path)
  --draft-log FILE     one line per decode window for draft-policy study

  --ppl-base FILE      llama.cpp KL-divergence base for ppl= requests
  --ppl-out FILE       where ppl= requests write their per-row lines
  --gpu-stages         capture the layer as three graphs (mixer / ffn+router / post)

                       real graph that --stage-timing cannot give.  Prints and exits.
  --expert-profile-save P  --serve: save what the adaptive tier learned (the experts in
                       VRAM, then the routing counted since the start) as a profile at P, on
                       QUIT and every --expert-profile-save-every MIN minutes (default 10;
                       0 = on QUIT only) between requests; a start with P already there
                       places that profile instead of the engine's; it is the format of
                       data/profiles
  --expert-cache N|auto  keep N expert blobs resident in VRAM and compute their rows on the
                       GPU.  Default auto with an expert profile.  auto = as many as fit in the VRAM
                       left after the weights, the session and --vram-reserve-mib
  --vram-reserve-mib N  VRAM left free on the primary GPU for graphs, scratch and the head when

  --peer-exclusive     with --resident-experts: experts on the peer are held only there, not

  --peer-reserve-mib N  VRAM the peer tier leaves free on its card (default 600)
  --adapt-every N      adaptive expert tier: a round every N decode windows (default 1 for a

  --adapt-decay F      factor the routing counts are multiplied by after each round (default
                       0.85 on a server with or without the peer tier, 0.7 with the layers
                       split over GPUs and outside --serve); lower forgets sooner
  --prefill-cpu-share F  share of the streamed prompt experts the CPU computes, 0 to 1 (default

  --adapt-swaps N      most experts a round swaps into the main GPU (default 96; 0 = off). On a

  --pool-workers N     CPU expert pool worker count.  Auto when not set: every physical core

  --pool-affinity MODE Which cores size the worker pool (workers are not pinned): all (one
                       worker per physical core), auto (hybrid CPUs: the P-cores minus the
                       host's, plus half the E-cores) or p-cores (the P-cores minus the host's).
                       Auto when not set.
  --mmap-experts       opt OUT of the default resident RAM copy, back to a file mapping.
